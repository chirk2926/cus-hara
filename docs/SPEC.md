# 仕様書 ―「カスハラ防衛線」

対象バージョン: 1.0.0。節ごとに「実装済み」「未検証」を明記する。数値の定義場所も併記するので、調整はそこを変える。
依頼者の指示との対応は [REQUIREMENTS_LOG.md](REQUIREMENTS_LOG.md)、作りは [DESIGN.md](DESIGN.md)、サーバーは [SERVER.md](SERVER.md)。

## 1. ゲーム概要

- ジャンル: 接客サバイバル（テキスト／音声入力＋簡易3D）。トーンは誇張されたコメディ。
- プレイヤーは店のスタッフ。理不尽なクレームをつけるお客さんに、**キレる前に**言葉で対応する。
- 遊び方: 1人用（シフト）と、2人の対戦（客役 vs 店員役）。
- 動作環境: Windows 10/11（64bit）。エンジンは Godot 4.5（Forward+）。配布: Steam / Microsoft Store（[MAINTENANCE.md](MAINTENANCE.md)）。
- 言語: 日本語・英語（9節）。
- AI: Claude（Anthropic）。**既定ではゲームサーバーがAIを呼び、APIキーはサーバーだけが持つ**（要件#24）。

## 3. 1人用モード（実装済み。CIでサーバー経由・台本の両方を自動プレイ）

定義: `scripts/solo_game.gd`

1. 1シフト = お客さん4人（`CUSTOMERS_PER_SHIFT`）。
2. お客さんごとに2つのゲージ（0〜100）。
   - **怒り**: 開始値30〜55。返事を考えている間、毎秒 `0.8 × patience × (1 + 0.08 × 何人目(0始まり))` × 返事の時間の倍率 上がる（要件#49で 1.25 / 0.15 から下げた。ふつうの気の長さ・開始40なら、1人目は約75秒で100）。採点待ち・セリフ表示中・休憩中は止まる。
   - **納得**: 0から始まり、正しい対応で上がる。
3. 返事を送ると採点され、怒り（-30〜+30）と納得（0〜+40。キーワード判定は最大+45）が変わる。
4. 終了条件（上から順）: 不当要求を飲んだ → **屈服** -600 ／ 怒り100（時間切れ含む）→ **激怒** -300 ／ 納得100 → **納得** `1000 + (100-怒り)×6 + max(0, 300 - ターン数×50)`。
5. シフト終了時、合計点でランク（`main.gd` の `RANKS`）: S ≥5600 / A ≥4000 / B ≥2400 / C ≥800 / D。ステージごとのハイスコアはPC内に保存。

### AIの使い方（設定「1人用のAI」= `GameSettings.solo_source`）
| 値 | 動き |
|---|---|
| `server`（既定） | サーバーの `/api/v1/solo/start`・`/solo/turn` に問い合わせる。サーバーにつながらないときは、そのお客さんから台本＋キーワード判定に切り替え、理由を付箋に出す |
| `own_key` | プレイヤー自身の Claude APIキーで直接呼ぶ（`scripts/llm_client.gd`）。失敗したターンはキーワード判定 |
| `offline` | 台本＋キーワード判定のみ |

### 入力
- 入力欄（200文字）＋ Enter または「返事をする」。接客用語のタグ5種は押すと文に足す。
- Esc または「休憩」で一時停止。

## 4. お客さんデータ（台本: `data/scenarios.json`、英語: `data/scenarios.en.json`）

台本もAI生成も同じ形の辞書。

| キー | 型 | 説明 |
|---|---|---|
| `title` / `name` | String | 呼び名 / 架空のフルネーム |
| `look` | Dictionary | `body_color` `skin_color` `hair_color`（#rrggbb）、`hair`（bald/short/long/perm/cap）、`build`（slim/normal/big）、`accessory`（none/glasses/mask/headphones/bag）、`height`（0.85〜1.15） |
| `memo` | String | スタッフが知っている事実と店の規定（プレイヤーへのヒント） |
| `opening` / `demand` | String | 最初のクレーム / 不当な要求の要約 |
| `patience` / `start_anger` | float / int | 0.7〜1.4 / 30〜55 |
| `solution_keywords` / `yield_keywords` | Array | 採点用。正しい解決策の語 / 屈服の語。**サーバーはクライアントに渡さない** |
| `lines` | Dictionary | 台本のみ。`calm` `angry` `neutral` `demand`（配列）、`resolved` `explode` `yielded` |

日本語と英語の台本は、同じ順番・同じ見た目の値で対応している。

## 5. 採点

結果の形（共通）: `anger_delta` / `resolve_delta` / `yielded` / `customer_reply` / `comment`（店長の一言）。

### 5.1 キーワード判定（サーバー `server/src/keyword_judge.ts` とクライアント `scripts/offline_judge.gd`。語は `data/judge_words.json`）
返答に含まれる語（英語は小文字にして部分一致）で加減点する。

| 分類 | 例 | 怒り | 納得 |
|---|---|---|---|
| 謝罪 | 申し訳／sorry | -8 | |
| 共感 | お気持ち／understand | -7 | |
| 傾聴 | 詳しく／could you tell me | -5 | +8 |
| 丁寧語 | ございます／please | -3 | |
| 解決策（お客さんごと、最大2語） | 交換／exchange | -6/語 | +24/語 |
| 毅然とした断り | いたしかねます／unable to | 謝罪も共感も無ければ +6 | +15 |
| 言い訳 | でも／not my fault | +8 | |
| 丁寧さが無い（`polite_pattern` に合わない） | | +8 | |
| 短すぎる（日本語6文字未満／英語3語未満） | | +10 | |
| 同じ返事の繰り返し | | +12 | 0にする |
| ゲーム外の話（10節） | コードを書いて／what model | +12 | 0にする |
| 暴言 | うるさい／shut up | +25 | 0にする |
| 謝罪だけを3回目以降 | | -2に固定 | |

`yield_keywords` を含み、否定語（ません／can't など）を含まない場合に屈服。「申し訳ございません」「no problem」などは否定語として数えない（`apology_forms`）。

### 5.2 AI判定（サーバー `server/src/llm.ts`。自分のキーのときは `scripts/llm_client.gd`）
- Claude Messages API。サーバーの既定モデルは `claude-haiku-5-5`（要件#33。環境変数 `CLAUDE_MODEL`）。モデルを選べるのは「自分のAPIキー」を使うときだけ。effort `low`、JSONスキーマで出力を固定。
- 呼び出し: お客さん生成（1人に1回）、店員の返答の採点（1回の返事に1回）、対戦の客役のセリフの採点。
- 失敗・回数上限のときはキーワード判定に切り替え、理由を表示する。

## 6. 対戦モード（実装済み。CIで2クライアントの自動対戦を文字・音声とも確認。人どうしの実戦は未検証）

定義: クライアント `scripts/versus_game.gd`、サーバー `server/src/match.ts` / `lobby.ts`。**進行・時間・判定・レーティングはすべてサーバーが決める**（要件#19。改ざんできない）。

### 6.1 遊び方の種類（要件#21, #22）
| 種類 | 相手 | レーティング |
|---|---|---|
| ランクマッチ | 同じ接続サーバー・同じ形式の人の中から、レーティングが近い人。許容差は 100 から毎秒15ずつ広がり、45秒で誰とでも | 変わる |
| フレンド対戦 | 部屋コード（6文字。I O 0 1 は使わない）を共有した相手だけ。部屋は15分で期限切れ。部屋を作った人の言語で進む | 変わらない（記録のみ） |

### 6.2 形式（要件#20）
| 形式 | 入力 |
|---|---|
| 文字 | 入力欄に書いて送る |
| 音声 | 「押して話す」ボタン（またはスペース）を押している間だけ録音。離すと送る。**相手にはすぐ声が届き**（ボイスチャット）、サーバーが文字起こしして判定する。マイクが無いときや、うまくいかないときは文字でも送れる |

音声は 16kHz・モノラル・μ-law、1回 0.1〜20秒。文字起こしが使えないサーバーでは、音声の形式は選べない。

### 6.3 試合の流れ
1. 試合 = 2ラウンド。ラウンドごとに客役と店員役を交代（最初の役は抽選）。ステージも抽選。
2. お客さんカード（人物・状況メモ・不当な要求）はAIが作る（12秒で間に合わなければ台本）。両者に見える。
3. ラウンドの手順:
   1. 客役が最初のクレームを言う（45秒。音声は+10秒）。空・時間切れならカードの文面を使う（ペナルティなし）。
   2. 店員役の番。考えている間、怒りが毎秒 `0.75 × patience` 上がる（要件#49で 1.1 から下げた）。100で時間切れ（客役の勝ち）。音声のときは10秒の猶予がある。声が聞き取れなかったときは怒り+5でもう一度。
   3. 店員の返答を採点（5節。AIまたはキーワード）。
   4. 客役が言い返す（35秒。音声は+10秒）。審判が採点する（下表）。
   5. 2〜4をくり返す。

客役のセリフの採点（AI。使えないときはキーワード判定 `judgeCustomerLine`）:

| セリフ | 効果 |
|---|---|
| 人物設定に沿った、筋の通った（ように聞こえる）圧力 | 怒り +0〜+12 |
| 無言・時間切れ | 納得 +12（店員に有利） |
| 度を越した暴言・脅し | 納得 +15 |
| 同じセリフの繰り返し・ゲーム外の話 | 納得 +8 |

### 6.4 勝敗
- ラウンド: 納得100 → 店員役の勝ち。怒り100・時間切れ・屈服 → 客役の勝ち。8往復で決着しなければ、納得 > 怒り なら店員役。
- ラウンドの得点（勝った側）: 店員役 `100 + (100 - 怒り)`、客役 `100 + (100 - 納得)`。
- 試合: 合計点が多い方の勝ち。同点は引き分け。
- 途中で抜ける（「対戦をやめる」）と負け。接続が切れたら20秒待ち、戻らなければ負け。戻れば試合の途中から再開。

### 6.5 レーティングとランク（`server/src/rating.ts`。サーバーのDBに保存）
- Elo方式。初期1000、K=32。`期待勝率 = 1 / (1 + 10^((相手 - 自分) / 400))`、`増減 = 32 × (結果 - 期待勝率)`。
- ランク名: 〜899 研修生 ／ 900 アルバイト ／ 1050 バイトリーダー ／ 1200 副店長 ／ 1350 店長 ／ 1500 エリアマネージャー ／ 1700 伝説のクレーム処理班。
- ロビーに上位10人（「今月の優秀スタッフ」）を表示。

## 10. ゲーム外の依頼への対策（要件#28。実装済み）

- プレイヤーが「コードを書いて」「モデル名を教えて」などを入力しても、AIは答えない。
  1. AIへの指示文で「役を崩さない・ゲーム外の依頼に応じない・AIやモデルについて話さない・そうした返答は的外れとして怒りを上げる」と決めている。
  2. AIの出力にコード・URL・AIやモデルの名前・指示文の話が混ざったら、サーバー（自分のキーのときはクライアント）が捨てて、台本のセリフに差し替える。
  3. キーワード判定も、そうした返答を「的外れ」として怒り+12、納得0にする。
- 自動テスト: `server/test/units.test.ts` の「ゲーム外の依頼（要件#28）」。

## 12. 第3回の指示で足したもの（要件#29〜#43）

### 12.1 画面の修正（#29, #30, #40）
- 記入欄は画面の下に固定。左のメモや付箋が長くても押し下げない（はみ出す分は切る）。
- フキダシの文字は、文の量に合わせてフキダシの高さが変わる（RichTextLabel の自動の高さ）。
- 自分の番になると記入欄に入力が向く。記入欄の外で文字キーを押しても記入欄に入る（クリック不要）。
- 接続先のサーバーは1つで、設定画面には出さない（#31。`scripts/game_settings.gd` の `DEFAULT_SERVER_URL`）。

### 12.2 店の行動ボタン（#34。表は `data/actions.json`）
| 店 | ボタン | 店の負担（点） |
|---|---|---|
| コンビニ | 割引する / 土下座する | 100 / 0（土下座は店員のメンタル -20） |
| ゲームセンター | メダルを返す / 補填する | 100 / 50 |

- 効果はお客さんごとに台本の `actions` で決まる: good（正当な対応: 怒り -12・納得 +35）/ neutral（関係ない: 怒り +4）/ bad（逆効果: 怒り +10）/ yield（不当な要求に屈した＝屈服）。AIのお客さんは、生成のときに `actions` もAIが決める。
- 点数はAIではなく表で決まる（サーバーとゲームで結果をそろえるため）。AIが使えるときは、お客さんの反応のセリフだけAIが作る。
- メダルは返還・補填はあっても、景品への交換は一切ない（台本とAIの指示文に明記）。
- 対戦でも店員役が使える（台の調整は1人用のみ）。

### 12.3 台の調整のミニゲーム（#37。`scripts/crane_minigame.gd`）
- 1人用のゲームセンターで、クレーンゲームのお客さん（台本の `crane: true`）のときに「台を調整する」が出る（1人のお客さんに1回）。
- カメラが台へ移動 → 景品をクリックしてつかみ、ドラッグで動かす（取り出し口の穴の上には置けない）→ アームの強さ（1〜10。店の規定は6まで）→「この台で遊んでもらう」。調整の時間は30秒。
- お客さんが遊ぶ: アームが動いて景品をつかみ、持ち上げて取り出し口へ。取れる確率は `取り出し口からの距離` と `アームの強さ` で決まる。外れると、持ち上げる途中か運ぶ途中で景品が落ちる。
- 取れた: 怒り -25・納得 +70。取れなかった: 怒り +8・納得 +5。規定外の強さにすると 150点の負担と店長の一言。

### 12.4 店員のメンタル（#38。1人用）
- シフトの初めに100。お客さんの怒りが上がると減り（上がった分 × 0.6）、激怒 -15、屈服 -10、土下座 -20。落ち着かせると +1、納得 +8。
- 0になると、そのお客さんは「早退」（-500点）になり、シフトが終わる。

### 12.5 返事の時間（#35）
- 設定「返事の時間」: ゆっくり（怒りの速さ ×0.6）/ ふつう / はやい（×1.4）。1人用と、自分が作ったフレンド対戦の部屋に効く。ランクマッチは公平のため全員「ふつう」。

### 12.6 BGM（#36）
- タイトル・コンビニ・ゲームセンター・対戦の4曲（`assets/bgm/*.ogg`。`tools/make_bgm.py` で作ったオリジナル）。曲の切り替えはクロスフェード。お客さんの怒りが高いと少し速く（高く）なる。音量は効果音と別に設定できる。

### 12.7 ネタ枠のお客さんと、転ぶ演出（#41, #42）
- 台本に各店2人のネタ枠（`rare: true`。出る重みは通常の1/4）。AIで作るときも約1割をネタ枠にする。
- お客さんが怒って帰るとき、約25%で転んで起き上がる。

### 12.8 EOS（#32）
- [EOS.md](EOS.md)。相手探しとフレンド招待を EOS、対戦の進行と判定とレーティングをゲームサーバー。EOS を呼ぶ部分は未実装（依頼者の開発者ポータル登録とSDKが必要）。

### 12.9 エンジンについて（#39, #43）

## 13. 第5回の指示で足したもの（要件#49〜#52）

### 13.1 難易度（#49）
- 1人用: 怒りの上がる速さ `0.8 × patience × (1 + 0.08 × 何人目)` × 返事の時間の倍率（ゆっくり 0.6／ふつう 1.0／はやい 1.4）。
- 対戦: 店員役の怒りの速さ `0.75 × patience`。客役の持ち時間は最初 45秒、言い返し 35秒（音声は +10秒）。

### 13.2 解像度（#51）
- 設定の「解像度」: 自動（使える画面に収まる一番大きい 16:9）／1280×720／1366×768／1600×900／1920×1080／2560×1440。
- 選んだ大きさが使える画面（タスクバーを除く）より大きければ、縦横の比を保って縮める。ウィンドウの最小は 960×540。フルスクリーンのときは使わない。
- 画面の部品は 1280×720 を基準に、ウィンドウに合わせて拡大・縮小する（stretch: canvas_items / expand）。横長・縦長では余白が広がるだけで、部品ははみ出さない。

### 13.3 たまに起きるイベント（#52。1人用）
- **要注意人物**: 2人目以降のお客さんが 18% の確率で（1シフト1回まで）、とびきり突飛なお客さんになる。
  - 「！要注意人物が来店！」の帯、派手な見た目（背が高い・派手な色・ヘッドホンなど）、名前に【要注意】。
  - 台本ではネタ枠（`rare`）から選ぶ。AIには「突拍子もなく、理屈が独特すぎて会話がかみ合わないコメディの人物。病気や障害を連想させる描写はしない」と頼む。
  - 納得させると点数 ×1.5。

### 14.3 難易度の調整: パワー設定・確率設定・テストプレイ（#55。`scripts/crane_minigame.gd`）

### 14.4 ペイアウト率と、クレーム・売上・店舗レビュー（#55, #56）
- **「取れない」クレームの出やすさ**: 「〇〇円使っても取れない」のお客さん（台本の `spend: true`）は、選ばれる重みが `30 ÷ ペイアウト率` 倍（10% で 3 倍、80% で 0.375 倍）。AIのお客さんは、確率 `min(0.8, 0.3 × 30 ÷ ペイアウト率)` でこの種類にする。
- **お客さんが言う金額**: 1個あたりの目安 × 0.6〜1.3 を 500円単位に丸めた額（最低 1,000円）。台本の `{spent}` が「4,000円」のように置き換わる。例: ペイアウト率 20%（1個あたり 5,500円）なら「4,000円入れても取れない！」くらい。
- **売上**（1人を接客するごとに入る）: コンビニ 2,500円。ゲームセンター 2,000円 ＋ クレーン 3,000円 × (1 − ペイアウト率) ÷ 0.7（30% で 3,000円、10% で 3,857円、80% で 857円）。行動の分を引き、屈服したら −1,000円。
- **店舗レビュー**（★1.0〜5.0）: 3.0 から、納得 +0.3、激怒 −0.4、屈服 −0.2、早退 −0.3。ゲームセンターは最後に (ペイアウト率 − 30) × 0.01 を足す（80% で +0.5、10% で −0.2）。
- **点数への反映**（依頼者の回答: 点数に足す）: 売上ボーナス ＝ (売上 − 基準) ÷ 20（基準: コンビニ 10,000円、ゲームセンター 20,000円）。レビューボーナス ＝ (レビュー − 3.0) × 400。どちらも合計点に足し、レシートに出す。
- レシート: 「クレーンのペイアウト率」（確率設定のときだけ）、売上と売上ボーナス、店舗レビュー（★）とレビューボーナス。

## 18. キーワード判定の精度（要件#73）と、オフラインの経験値（要件#74）

### 18.1 キーワード判定（AIを使わないときの採点）の改善
ゲームの `scripts/offline_judge.gd` とサーバーの `server/src/keyword_judge.ts` で同じ規則（語は `data/judge_words.json`）。
- **屈服は「節」ごとに見る**: 返事を「、」「。」「！」「？」（英語は , . ! ? と but）で区切り、不当な要求の語と否定（できません 等）が**同じ節**にあるかで判定する。以前は、返事のどこかに否定があれば屈服にならなかった（「無料で交換します、返金はできません」が見逃されていた）。
- **言い訳の誤判定を減らす**: 「いつでも」「何でも」などの「でも」は言い訳に数えない（`excuse_exempt`）。「でも」「but」「但是」などのつなぎ言葉（`excuse_soft`）は、同じ返事に解決策か丁寧な断りがあれば言い訳に数えない（「〜はいたしかねますが、代わりに〜」は良い返事）。
- **ほぼ同じ返事のくり返し**: 前の返事との似ている度合い（日本語・中国語は2文字ずつ、英語は単語で比べる）が 0.8 以上なら、くり返しとして扱う（納得は上がらない）。
- **メモの中身に触れた返事**: 解決のキーワードが無くても、引き継ぎメモの中の語（漢字・カタカナの語、英語は4文字以上の単語）に2つ以上触れていれば、怒り −3・納得 +10（付箋:「メモの中身に触れているのはいい。あと一歩、具体的に。」）。よくある語（申し訳・お客様 など）は `stop_tokens` で除く。
- **謝ってばかり**: それまでの返事で2回以上謝っていたら、謝罪の効き（怒り −8）を −3 に減らす。
- **質問して聞き出す**: 丁寧な言い方で「？」を使って質問していれば、「話を聞く」に数える（怒り −5・納得 +8）。
- テスト: `server/test/units.test.ts` の「キーワード判定の精度（要件#73）」。

### 18.2 オフラインのときは経験値なし（#74）
- 1人用で、台本とキーワード判定（AIを使わない「オフライン」）のお客さんが1人でもいたシフトは、メンタルランク A の経験値が入らない（タイムカードに「オフラインのため経験値なし」）。設定で「AIを使わない（台本）」を選んだときと、サーバーにつながらず台本に切り替わったときの両方。
- 年齢確認のお客さんは、もともとゲームの中だけで判定するので数えない。

## 26. 不適切な言葉のブロック・コードのロック・画面の設定（要件#94, #95）
- **不適切な言葉のブロック**: 入力欄から送る前に、ゲームの中で確かめる（`scripts/moderation.gd`。語は `data/moderation_words.json` で、サーバーと共通）。当たったら送らず「不適切な言葉が含まれているため送れません」と出す（1人用・対戦とも）。止めるのは性的な内容・差別・命を脅かす言葉（「死ね」「殺すぞ」など）・個人情報（電話番号・メールアドレス）。**「バカ」「アホ」「クソ店員」「ふざけるな」くらいの暴言は止めない**。英語の語は単語の区切りで見る（cocktail・Sussex は止めない）。金額（「10000000円」）は電話番号と見なさない。
- 対戦はサーバーでも同じ語と AI で確かめる（声の文字起こしや、ゲームの改造ですり抜けた場合。伏せ字・警告・3回で負け）。
- **名前**: フロアネームに不適切な言葉があれば保存しない（「その名前は使えません」）。サーバーも名前の変更を断り（`name_not_allowed`）、ゲストを作るときは既定の名前にする。AI が使えるときは AI でも確かめる。
- **コードのロック**: 配る exe の中のスクリプトと素材を AES-256 で暗号化する（CI。docs/MAINTENANCE.md 2節）。スクリプトはテキストではなく圧縮したトークンで入れる。CI は exe の中にスクリプトの名前がそのまま見えないことと、暗号化した exe が Windows で起動して遊べることを確かめる。注意: 鍵は exe の中にあるので、時間をかければ取り出せる（完全には防げない）。大事な判定（レート・対戦の勝ち負け・AI の API キー）はもともとサーバーにあり、exe をいじっても変えられない。
- **画面の設定**: 解像度に 16:10・21:9・4K を追加。「描画の解像度」（100 / 85 / 75 / 50%。3D の部分だけを小さく描いて FSR で拡大する。文字はいつもくっきり）、「垂直同期」（オン・アダプティブ・オフ）、「フレームレートの上限」（上限なし・30〜240）、「可変リフレッシュレート（G-SYNC / FreeSync）」。可変リフレッシュレートをオンにすると、排他のフルスクリーン・垂直同期オン・上限をモニターのリフレッシュレート − 3 にする（別のモニターに移ったら合わせ直す）。動きはすべてフレームの時間で計算しているので、フレームレートが変わっても速さは同じ。

## 29. メダルゲーム・ビデオゲームの台の問題（要件#99）

- **1人用**: 「筐体を見に行く」→ 自分だけの3Dの場面（`scripts/repair_scene.gd`・`scripts/repair_stage.gd`）でカメラが筐体の前へ。メダルは「筐体を開ける」（鍵のタイミング）、ビデオは「操作パネルを開ける」をしてから、中の対応ができる。対応ごとに簡単なミニゲーム（叩く: 3回押す／分解: ネジを番号の順に外す／補充・修理: 押したままにする／確かめる: 4回押す／コネクタ・鍵: 緑のところで止める）と、扉・レール・補充口・抽選機・パネル・コネクタが動く。
- 対応には時間がかかり（分解 14 秒・修理 10 秒・補充 8 秒・叩く 3 秒など）、カウンターに戻ったとき、その分だけ怒りがゆるやかに上がる（1 秒あたり 0.45）。した対応は順に判定する（本当に直す対応は `fixed`: 怒り -18・納得 +55）。
- 台パン・大声: 「様子を見に行く」で、ビデオゲームコーナーの場面に本人がこちらを向いて立っている。会話の吹き出し・入力欄はそのまま。本人が納得すれば「ドンッ！」が消え、カウンターに戻って知らせてくれたお客さんがお礼を言う。
- **対戦**: 場面には行かず、対応はふつうのボタン（叩く・分解・補充・修理・確かめる・コネクタ）。「筐体を見に行く」「様子を見に行く」は出さない。
- **台本**: メダル詰まり奥さん・払い出しゼロ男・抽選機止まった青年・ボタン反応しない男・台パン通報の常連さん・大声に困るおじさん（3言語）。**AI のお客さん**: 用件の種類に「台の不具合・迷惑なお客さんの通報」を足し、AI は problem の種類だけを選ぶ（台と効果はサーバーが表から決める）。

## 33. テスト後の修正 その4（要件#106）
- **引っかかった景品**: 店の規定は「スタッフが台の扉を開けて、その景品をその場で手渡しできる（ほかの景品を無料で渡す・返金はできない）」。AI がお客さんを作る指示にも書いた。「〇〇円使っても取れない」お客さんは景品が引っかかっていないので、`crane_stuck` は neutral にし、ゲームは「景品が引っかかっています」の表示とボタンを出さない（`ShopActions.is_stuck`）。
- **景品を取りやすい位置へ**: 景品を動かしたら、お客さんはその場では遊ばない。ミニゲームの「これで頑張ってもらう」で、結果 `crane_moved`（怒り -18・納得 +60）。景品だけが目当てのお客さんはそこで納得、ほかの要求があれば話は続く。称号「景品配置のプロ」はこの対応の回数。
- **話のまとめ**: 1人用で、納得 70 以上・怒り 40 以下のときに正しい対応（納得が上がり怒りが上がらない）をしたら、そこで納得（`SETTLE_AT`・`SETTLE_ANGER`）。AI は、話が実質的に片づいたら納得の残りを一気に埋めてよい（1人用は最大 100、対戦は 40 まで）。納得で終わるのにお客さんのセリフが問いかけや怒りのままなら、締めの一言（台本の resolved）を足す。
- **帽子・マスク**: 年齢確認のお客さんは 30% で帽子、20% でマスク。身分証の写真には写っていない。「帽子を取ってもらう」「マスクを外してもらう」で外れ、顔を写真と見比べられる。外さずに入店・販売を認めて正しかったときは、店長のひと言でヒントを出す。
- **キレるまでの秒数**: 管理画面の 設定 →「1人用」に、返事の時間（かめ・うさぎ・チーター）ごとの秒数（怒り 0 から 100 まで、気の長さふつうの1人目）。既定は 300・180・128 秒。`/api/v1/info` の `snap_seconds` で配り、サーバーにつないでいるゲームだけに効く。
- **ペイアウト率と給与**: 60% 以上は景品代とスタッフの時給・電気代で赤字。給与は 60% で 0.7倍、10% ごとに 0.2 下がり、0.3倍まで（`Shop.payout_pay_mul`）。レシートに注意書き。
- **要注意人物**: シフト中に来る確率を 0.18 → 0.07、台本のネタ枠がふつうに選ばれる重みを 0.25 → 0.1（ゲームとサーバー）。
- **テストモード**: デバッグパネル（F12）の「次のお客さんの種類（毎回）」で、引っかかった景品・取れない（本当／うそ）・メダル詰まり・メダル切れ・抽選機・ボタン（本当／うそ）・台パン・大声・年齢確認（帽子・マスク）を選べる。台本のお客さんから作る（ゲームセンター）。「においのイベントを毎回」も足した。

## 35. 台を直したあと・レール分解の手順（要件#110）
- 1人用で台を直す対応（効果が `fixed` か `hit`）をしたら、そのお客さんの間は「直した」と覚える（`solo_game.gd` の `_machine_fixed`）。そのあと「メダル補填」「クレジット補填」をすると、納得が 100 になり対応が終わる。
- 直したあとにもう一度「筐体を見に行く」と、直った台が出る（`repair_scene.gd` の `fixed`）。中を見ると「さっき直したところ」。そこでした対応はお客さんへの対応に数えない。
- 払い出しレールの分解のミニゲーム: ① ドライバー（押したまま 4 秒）でネジ 4 本が順に外れる → ② 押したまま 1.5 秒でレールが手前に出る → ③ 詰まったメダルを 1 枚ずつ取る（ボタン。3D のメダルも 1 枚ずつ消える）→ ④ 押したままでレールが戻りネジが締まる（合計で 15 秒になるまで。最低 4 秒）。
