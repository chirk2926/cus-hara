# 仕様書 ―「カスハラ防衛線」

対象バージョン: 0.2.0（開発中）。節ごとに「実装済み」「未検証」を明記する。数値の定義場所も併記するので、調整はそこを変える。
依頼者の指示との対応は [REQUIREMENTS_LOG.md](REQUIREMENTS_LOG.md)、作りは [DESIGN.md](DESIGN.md)、サーバーは [SERVER.md](SERVER.md)。

## 1. ゲーム概要

- ジャンル: 接客サバイバル（テキスト／音声入力＋簡易3D）。トーンは誇張されたコメディ。
- プレイヤーは店のスタッフ。理不尽なクレームをつけるお客さんに、**キレる前に**言葉で対応する。
- 遊び方: 1人用（シフト）と、2人の対戦（客役 vs 店員役）。
- 動作環境: Windows 10/11（64bit）。エンジンは Godot 4.5（Forward+）。配布: Steam / Microsoft Store（[MAINTENANCE.md](MAINTENANCE.md)）。
- 言語: 日本語・英語（9節）。
- AI: Claude（Anthropic）。**既定ではゲームサーバーがAIを呼び、APIキーはサーバーだけが持つ**（要件#24）。

## 3. 1人用モード（実装済み。CIでサーバー経由・台本の両方を自動プレイ）

定義: `scripts/solo_game.gd`

1. 1シフト = お客さん4人（`CUSTOMERS_PER_SHIFT`）。
2. お客さんごとに2つのゲージ（0〜100）。
   - **怒り**: 開始値30〜55。返事を考えている間、毎秒 `1.25 × patience × (1 + 0.15 × 何人目(0始まり))` 上がる。採点待ち・セリフ表示中・休憩中は止まる。
   - **納得**: 0から始まり、正しい対応で上がる。
3. 返事を送ると採点され、怒り（-30〜+30）と納得（0〜+40。キーワード判定は最大+45）が変わる。
4. 終了条件（上から順）: 不当要求を飲んだ → **屈服** -600 ／ 怒り100（時間切れ含む）→ **激怒** -300 ／ 納得100 → **納得** `1000 + (100-怒り)×6 + max(0, 300 - ターン数×50)`。
5. シフト終了時、合計点でランク（`main.gd` の `RANKS`）: S ≥5600 / A ≥4000 / B ≥2400 / C ≥800 / D。ステージごとのハイスコアはPC内に保存。

### AIの使い方（設定「1人用のAI」= `GameSettings.solo_source`）
| 値 | 動き |
|---|---|
| `server`（既定） | サーバーの `/api/v1/solo/start`・`/solo/turn` に問い合わせる。サーバーにつながらないときは、そのお客さんから台本＋キーワード判定に切り替え、理由を付箋に出す |
| `own_key` | プレイヤー自身の Claude APIキーで直接呼ぶ（`scripts/llm_client.gd`）。失敗したターンはキーワード判定 |
| `offline` | 台本＋キーワード判定のみ |

### 入力
- 入力欄（200文字）＋ Enter または「返事をする」。接客用語のタグ5種は押すと文に足す。
- Esc または「休憩」で一時停止。

## 4. お客さんデータ（台本: `data/scenarios.json`、英語: `data/scenarios.en.json`）

台本もAI生成も同じ形の辞書。

| キー | 型 | 説明 |
|---|---|---|
| `title` / `name` | String | 呼び名 / 架空のフルネーム |
| `look` | Dictionary | `body_color` `skin_color` `hair_color`（#rrggbb）、`hair`（bald/short/long/perm/cap）、`build`（slim/normal/big）、`accessory`（none/glasses/mask/headphones/bag）、`height`（0.85〜1.15） |
| `memo` | String | スタッフが知っている事実と店の規定（プレイヤーへのヒント） |
| `opening` / `demand` | String | 最初のクレーム / 不当な要求の要約 |
| `patience` / `start_anger` | float / int | 0.7〜1.4 / 30〜55 |
| `solution_keywords` / `yield_keywords` | Array | 採点用。正しい解決策の語 / 屈服の語。**サーバーはクライアントに渡さない** |
| `lines` | Dictionary | 台本のみ。`calm` `angry` `neutral` `demand`（配列）、`resolved` `explode` `yielded` |

日本語と英語の台本は、同じ順番・同じ見た目の値で対応している。

## 5. 採点

結果の形（共通）: `anger_delta` / `resolve_delta` / `yielded` / `customer_reply` / `comment`（店長の一言）。

### 5.1 キーワード判定（サーバー `server/src/keyword_judge.ts` とクライアント `scripts/offline_judge.gd`。語は `data/judge_words.json`）
返答に含まれる語（英語は小文字にして部分一致）で加減点する。

| 分類 | 例 | 怒り | 納得 |
|---|---|---|---|
| 謝罪 | 申し訳／sorry | -8 | |
| 共感 | お気持ち／understand | -7 | |
| 傾聴 | 詳しく／could you tell me | -5 | +8 |
| 丁寧語 | ございます／please | -3 | |
| 解決策（お客さんごと、最大2語） | 交換／exchange | -6/語 | +24/語 |
| 毅然とした断り | いたしかねます／unable to | 謝罪も共感も無ければ +6 | +15 |
| 言い訳 | でも／not my fault | +8 | |
| 丁寧さが無い（`polite_pattern` に合わない） | | +8 | |
| 短すぎる（日本語6文字未満／英語3語未満） | | +10 | |
| 同じ返事の繰り返し | | +12 | 0にする |
| ゲーム外の話（10節） | コードを書いて／what model | +12 | 0にする |
| 暴言 | うるさい／shut up | +25 | 0にする |
| 謝罪だけを3回目以降 | | -2に固定 | |

`yield_keywords` を含み、否定語（ません／can't など）を含まない場合に屈服。「申し訳ございません」「no problem」などは否定語として数えない（`apology_forms`）。

### 5.2 AI判定（サーバー `server/src/llm.ts`。自分のキーのときは `scripts/llm_client.gd`）
- Claude Messages API。サーバーの既定モデルは `claude-haiku-5-5`（要件#33。環境変数 `CLAUDE_MODEL`）。モデルを選べるのは「自分のAPIキー」を使うときだけ。effort `low`、JSONスキーマで出力を固定。
- 呼び出し: お客さん生成（1人に1回）、店員の返答の採点（1回の返事に1回）、対戦の客役のセリフの採点。
- 失敗・回数上限のときはキーワード判定に切り替え、理由を表示する。

## 6. 対戦モード（実装済み。CIで2クライアントの自動対戦を文字・音声とも確認。人どうしの実戦は未検証）

定義: クライアント `scripts/versus_game.gd`、サーバー `server/src/match.ts` / `lobby.ts`。**進行・時間・判定・レーティングはすべてサーバーが決める**（要件#19。改ざんできない）。

### 6.1 遊び方の種類（要件#21, #22）
| 種類 | 相手 | レーティング |
|---|---|---|
| ランクマッチ | 同じ言語・同じ形式の人の中から、レーティングが近い人。許容差は 100 から毎秒15ずつ広がり、45秒で誰とでも | 変わる |
| フレンド対戦 | 部屋コード（6文字。I O 0 1 は使わない）を共有した相手だけ。部屋は15分で期限切れ。部屋を作った人の言語で進む | 変わらない（記録のみ） |

### 6.2 形式（要件#20）
| 形式 | 入力 |
|---|---|
| 文字 | 入力欄に書いて送る |
| 音声 | 「押して話す」ボタン（またはスペース）を押している間だけ録音。離すと送る。**相手にはすぐ声が届き**（ボイスチャット）、サーバーが文字起こしして判定する。マイクが無いときや、うまくいかないときは文字でも送れる |

音声は 16kHz・モノラル・μ-law、1回 0.1〜20秒。文字起こしが使えないサーバーでは、音声の形式は選べない。

### 6.3 試合の流れ
1. 試合 = 2ラウンド。ラウンドごとに客役と店員役を交代（最初の役は抽選）。ステージも抽選。
2. お客さんカード（人物・状況メモ・不当な要求）はAIが作る（12秒で間に合わなければ台本）。両者に見える。
3. ラウンドの手順:
   1. 客役が最初のクレームを言う（35秒。音声は+10秒）。空・時間切れならカードの文面を使う（ペナルティなし）。
   2. 店員役の番。考えている間、怒りが毎秒 `1.1 × patience` 上がる。100で時間切れ（客役の勝ち）。音声のときは10秒の猶予がある。声が聞き取れなかったときは怒り+5でもう一度。
   3. 店員の返答を採点（5節。AIまたはキーワード）。
   4. 客役が言い返す（25秒。音声は+10秒）。審判が採点する（下表）。
   5. 2〜4をくり返す。

客役のセリフの採点（AI。使えないときはキーワード判定 `judgeCustomerLine`）:

| セリフ | 効果 |
|---|---|
| 人物設定に沿った、筋の通った（ように聞こえる）圧力 | 怒り +0〜+12 |
| 無言・時間切れ | 納得 +12（店員に有利） |
| 度を越した暴言・脅し | 納得 +15 |
| 同じセリフの繰り返し・ゲーム外の話 | 納得 +8 |

### 6.4 勝敗
- ラウンド: 納得100 → 店員役の勝ち。怒り100・時間切れ・屈服 → 客役の勝ち。8往復で決着しなければ、納得 > 怒り なら店員役。
- ラウンドの得点（勝った側）: 店員役 `100 + (100 - 怒り)`、客役 `100 + (100 - 納得)`。
- 試合: 合計点が多い方の勝ち。同点は引き分け。
- 途中で抜ける（「対戦をやめる」）と負け。接続が切れたら20秒待ち、戻らなければ負け。戻れば試合の途中から再開。

### 6.5 レーティングとランク（`server/src/rating.ts`。サーバーのDBに保存）
- Elo方式。初期1000、K=32。`期待勝率 = 1 / (1 + 10^((相手 - 自分) / 400))`、`増減 = 32 × (結果 - 期待勝率)`。
- ランク名: 〜899 研修生 ／ 900 アルバイト ／ 1050 バイトリーダー ／ 1200 副店長 ／ 1350 店長 ／ 1500 エリアマネージャー ／ 1700 伝説のクレーム処理班。
- ロビーに上位10人（「今月の優秀スタッフ」）を表示。

## 7. アカウントと保存データ

- 初回の起動時、サーバーにゲストのアカウントを作る（名前だけ。メール等は取らない）。トークンはPCの設定ファイルに保存し、サーバーはハッシュだけを持つ。
- PC（`user://settings.cfg`、Windows では `%APPDATA%\Godot\app_userdata\カスハラ防衛線\`）: 言語、トークン、名前、最後に受け取った自分の情報、AIの使い方、自分のAPIキー（平文）、モデル、音量、話すキー、フルスクリーン、ハイスコア。
- サーバー（SQLite）: プレイヤー（名前・レーティング・勝敗）と対戦記録。

## 10. ゲーム外の依頼への対策（要件#28。実装済み）

- プレイヤーが「コードを書いて」「モデル名を教えて」などを入力しても、AIは答えない。
  1. AIへの指示文で「役を崩さない・ゲーム外の依頼に応じない・AIやモデルについて話さない・そうした返答は的外れとして怒りを上げる」と決めている。
  2. AIの出力にコード・URL・AIやモデルの名前・指示文の話が混ざったら、サーバー（自分のキーのときはクライアント）が捨てて、台本のセリフに差し替える。
  3. キーワード判定も、そうした返答を「的外れ」として怒り+12、納得0にする。
- 自動テスト: `server/test/units.test.ts` の「ゲーム外の依頼（要件#28）」。

## 12. 第3回の指示で足したもの（要件#29〜#43）

### 12.1 画面の修正（#29, #30, #40）
- 記入欄は画面の下に固定。左のメモや付箋が長くても押し下げない（はみ出す分は切る）。
- フキダシの文字は、文の量に合わせてフキダシの高さが変わる（RichTextLabel の自動の高さ）。
- 自分の番になると記入欄に入力が向く。記入欄の外で文字キーを押しても記入欄に入る（クリック不要）。
- 接続先のサーバーは1つで、設定画面には出さない（#31。`scripts/game_settings.gd` の `DEFAULT_SERVER_URL`）。

### 12.2 店の行動ボタン（#34。表は `data/actions.json`）
| 店 | ボタン | 店の負担（点） |
|---|---|---|
| コンビニ | 割引する / 土下座する | 100 / 0（土下座は店員のメンタル -20） |
| ゲームセンター | メダルを返す / 補填する | 100 / 50 |

- 効果はお客さんごとに台本の `actions` で決まる: good（正当な対応: 怒り -12・納得 +35）/ neutral（関係ない: 怒り +4）/ bad（逆効果: 怒り +10）/ yield（不当な要求に屈した＝屈服）。AIのお客さんは、生成のときに `actions` もAIが決める。
- 点数はAIではなく表で決まる（サーバーとゲームで結果をそろえるため）。AIが使えるときは、お客さんの反応のセリフだけAIが作る。
- メダルは返還・補填はあっても、景品への交換は一切ない（台本とAIの指示文に明記）。
- 対戦でも店員役が使える（台の調整は1人用のみ）。

### 12.3 台の調整のミニゲーム（#37。`scripts/crane_minigame.gd`）
- 1人用のゲームセンターで、クレーンゲームのお客さん（台本の `crane: true`）のときに「台を調整する」が出る（1人のお客さんに1回）。
- カメラが台へ移動 → 景品をクリックしてつかみ、ドラッグで動かす（取り出し口の穴の上には置けない）→ アームの強さ（1〜10。店の規定は6まで）→「この台で遊んでもらう」。調整の時間は30秒。
- お客さんが遊ぶ: アームが動いて景品をつかみ、持ち上げて取り出し口へ。取れる確率は `取り出し口からの距離` と `アームの強さ` で決まる。外れると、持ち上げる途中か運ぶ途中で景品が落ちる。
- 取れた: 怒り -25・納得 +70。取れなかった: 怒り +8・納得 +5。規定外の強さにすると 150点の負担と店長の一言。

### 12.4 店員のメンタル（#38。1人用）
- シフトの初めに100。お客さんの怒りが上がると減り（上がった分 × 0.6）、激怒 -15、屈服 -10、土下座 -20。落ち着かせると +1、納得 +8。
- 0になると、そのお客さんは「早退」（-500点）になり、シフトが終わる。

### 12.5 返事の時間（#35）
- 設定「返事の時間」: ゆっくり（怒りの速さ ×0.6）/ ふつう / はやい（×1.4）。1人用と、自分が作ったフレンド対戦の部屋に効く。ランクマッチは公平のため全員「ふつう」。

### 12.6 BGM（#36）
- タイトル・コンビニ・ゲームセンター・対戦の4曲（`assets/bgm/*.ogg`。`tools/make_bgm.py` で作ったオリジナル）。曲の切り替えはクロスフェード。お客さんの怒りが高いと少し速く（高く）なる。音量は効果音と別に設定できる。

### 12.7 ネタ枠のお客さんと、転ぶ演出（#41, #42）
- 台本に各店2人のネタ枠（`rare: true`。出る重みは通常の1/4）。AIで作るときも約1割をネタ枠にする。
- お客さんが怒って帰るとき、約25%で転んで起き上がる。

### 12.8 EOS（#32）
- [EOS.md](EOS.md)。相手探しとフレンド招待を EOS、対戦の進行と判定とレーティングをゲームサーバー。EOS を呼ぶ部分は未実装（依頼者の開発者ポータル登録とSDKが必要）。

### 12.9 エンジンについて（#39, #43）
- [ENGINE.md](ENGINE.md)。ゲーム内に「ライセンス」画面を追加。
