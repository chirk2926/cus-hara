# UIガイド ―「AIっぽくない」画面の作り方

要件#23 で「今のUIはAIっぽい」と指摘された。このガイドは、調べた結果と、このゲームで守る具体的な決まりをまとめたもの。
画面を足すとき・直すときは、必ずこのガイドに沿って作り、最後に 5節のチェックをする。

## 1. 調べたこと

AIが作るUIに共通する「それっぽさ」は、ネット上で「AI slop（AIの量産品）」と呼ばれ、典型的な特徴に名前を付けて避ける考え方が広まっている。主な参考:

- Impeccable（pbakaus/impeccable）の「AI slop test」と名前付きのアンチパターン集。これを取り込んだ wystack agent-kit の `references/anti-patterns.md`（npm `@wystack/agent-kit@0.12.0` で中身を確認）。
- 検索結果の要約で多く挙がっていた指摘: 紫〜青のグラデーション、全要素に同じ角丸、カードの入れ子、暗い背景に光る差し色、Interなど定番フォント、中央寄せの決まりきった構成。直し方として「役割を決めた4〜6色の名前付きパレット」「角丸と影の強さを階層で変える」「デザインの方向性を文書にして守る」。
- ゲームUIの例として Persona 5 の分析（赤・黒・白に絞った配色、太い見出し、斜めの配置。情報は白い面の側にまとめる）。メニューを画面ごとに作り分けている点。
- 日本のコンビニのPOP・レシートのデザイン（POPは役割で種類を分ける: 商品説明、天吊りの案内、レジ横の告知）。

**AI slop test**: 「この画面、AIが作ったんだよ」と見せたとき、すぐ信じられてしまうなら失敗。「どうやって作ったの？」と聞かれる画面を目指す。

### 以前の画面にあった「AIっぽさ」（作り直し前の記録）
| 名前 | 以前の状態 |
|---|---|
| Cardocalypse（何でもカード） | メモ、店長の一言、ゲージ、入力欄、上部バーがすべて同じ角丸の暗い半透明パネル |
| 均一な角丸 | すべての部品が角丸12〜14px |
| 半透明の多用 | 背景を透かした黒パネルが画面の半分を覆っていた（「透明度は色が決まっていない証拠」） |
| 全ボタンが主役 | 定型文、送信、メニュー、タイトルの各ボタンが全部べた塗りの色ボタン |
| モーダル頼み | 設定・遊び方・結果・メニューがすべて画面中央の同じ暗い箱 |
| 1書体 | すべて Noto Sans JP |

## 2. このゲームの方向性:「お店の備品でできた画面」

画面の部品を、**その店に実際にありそうな物**として作る（ゲームの世界の中にある物として見せる）。
抽象的な「パネル」は作らない。新しい部品を作るときは「これは店の何か？」を先に決める。

| 画面の要素 | 店の物 | 見た目の要点 |
|---|---|---|
| 状況メモ | 引き継ぎメモ（バックヤードの紙） | 罫線の入った紙、上辺にマスキングテープ、手書き風の文字 |
| 店長の一言 | 付箋 | 黄色の小さな正方形、手書き風、わずかに傾ける |
| お客さんのセリフ | マンガのフキダシ | 白地に太い黒線、しっぽがお客さんの方を向く。怒りが強いとギザギザ |
| 怒り・納得ゲージ | POSレジのお客様用表示器 | 暗い緑の液晶にドット文字。数字は7セグ風の大きなドット文字 |
| 返事の入力欄 | レジ横の伝言用ホワイトボード／記入欄 | 白い紙に下線だけ。枠で囲まない |
| 定型文 | レジ横の「接客用語」カード | 薄い紙のタグ。色ボタンにしない |
| 結果 | レシート | 細長い紙に品目（お客さん）と小計・合計。ドット文字 |
| タイトル | 店頭の求人ポスター（「スタッフ募集」） | 極太見出し、赤と黄、紙を斜めに貼る |
| 一時停止 | 「休憩中」の札 | |
| 対戦ロビー | バックヤードのシフト表・掲示板 | |

## 3. 決まり（具体的な数値）

### 色（`scripts/ui_kit.gd` の定数だけを使う）
| 名前 | 役割 | 値 |
|---|---|---|
| PAPER | 紙（面の大半） | `#f3eee3` |
| PAPER_DIM | 紙の影・罫線 | `#d9d1c0` |
| INK | 文字・線（真っ黒にしない） | `#24212b` |
| INK_SOFT | 補足の文字 | `#6b6574` |
| SHU | 朱赤。主役のボタン1つ・怒り | `#d23f2f` |
| POP | 黄。付箋・強調（1画面に少しだけ） | `#ffd23f` |
| LCD_BG / LCD_ON | レジ表示器の液晶 | `#1f2b22` / `#b8f28a` |
| OK | 納得 | `#2f8f5b` |

- 1画面で彩度の高い色は SHU と POP の2つまで。グラデーションは使わない（3D空間の照明は別）。
- 純粋な黒 `#000` と白 `#fff` は使わない。
- 透明度で色を作らない。例外は画面全体を暗くする幕（`#000` ではなく INK の 60%）とフォーカス表示だけ。

### 書体（役割ごとに1つ。混ぜない）
| 書体 | 役割 |
|---|---|
| Noto Sans JP Medium / ExtraBold | 本文、ボタン、フキダシのセリフ |
| Yusei Magic（手書きマーカー風） | 手書きの物: 引き継ぎメモ、付箋、POP |
| DotGothic16（ドット文字） | 機械が表示する物: レジ表示器、レシート、残り秒数 |
| Dela Gothic One（極太） | 看板・ポスターの見出し、大きな判定（「ブチギレ！」など） |

サイズは 14 / 18 / 22 / 30 / 48 の5段階に限る（ドット文字の数字だけは 56 も可）。

### 形・影
- 角丸は部品の役割で変える。紙: 0〜2px。付箋: 0。フキダシ: 楕円に近い形（自前で描画）。タグ: 4px。**同じ角丸を全部に使わない。**
- 影はぼかさない「ずらしただけの影」（紙を重ねた感じ）。ずらし量 3〜6px、色は INK の 25%。ぼかし影・光るふちは使わない。
- カードの中にカードを入れない。

### ボタン
- 1画面で主役のボタン（べた塗り SHU）は1つだけ。ほかは「紙のタグ」か「下線付きの文字」。
- ラベルは「動詞＋目的語」: 「OK」「決定」ではなく「出勤する」「返事を渡す」「部屋を作る」。

### 配置
- 中央寄せの箱を基本にしない。左寄せ・非対称を基本にする。
- お客さんの顔（画面中央の上半分）は何も重ねない。
- 余白は 4 の倍数（4, 8, 12, 16, 24, 32, 48）。部品の中の余白と、部品どうしの間隔を同じにしない。

### 動き
- 跳ねる・弾むイージングは使わない（減速して止まる `EASE_OUT` を使う）。
- 演出は「ここぞ」の1か所に集める（判定の瞬間）。常に何かが動いている状態にしない。

### 文言
- 「エラーが発生しました」で終わらせない。何が起きて、どうすればよいかを書く。
- お店の言葉を使う（「スコア」より「売上」…は分かりにくいので、点数はそのまま「点」でよい。迷ったら分かりやすさを優先）。

## 4. 実装の場所

- 色・書体・部品の作り方は `scripts/ui_kit.gd` に集める。画面のスクリプトで色の数値を直接書かない。
- 自前で描く部品（フキダシ、レシートのギザギザ、テープ）は `scripts/ui_paper.gd` に置く。

## 5. 仕上げのチェック（画面を足したら毎回）

1. `[shots]` 付きでプッシュし、`docs/screenshots/` の画像で見る。
2. 次に当てはまらないか確かめる: 何でもカード／同じ角丸／半透明の黒パネル／主役ボタンが2つ以上／中央の暗い箱／書体の役割違い／グラデーション。
3. 目を細めて見て、いちばん大事な物（お客さんの顔とセリフ）がいちばん目立つか。
4. AI slop test を自問する。

## 6. 2回目の見直し（要件#96、2026-11-19）

### 6.1 追加で調べたこと
- 「AI slop」のチェックリストがさらに増えていた。新しく挙がっていた特徴: **同じ枠・同じ角丸のボタンがどの画面にも並ぶ**、**同じ大きさのカードを3つ横に並べる構成**、**中身の少ないカードの格子**、**0 や丸い数字ばかりの統計**、**既定のまま残った部品（灰色のスクロールバー・チェックボックス・選択肢の一覧）**、**1画面に主役のボタンが2つ以上**、「やり方を変えたつもりで、置きかえる案がない」こと。直し方は「禁止するだけでなく、代わりの意図ある選び方を決める」（参考: GitHub の Laith0003/ux-skill「Anti-AI slop ban list」、Impeccable のアンチパターン集、各種の解説記事。ただし多くは個人・企業のブログで、決まった基準ではない。目安として使う）。
- ゲームの UI では、**画面の部品を世界の中の物として作る（ダイエジェティック）**と「どうやって作ったの？」と聞かれる側になる。物として筋が通っていること（Dead Space で「未来の画面に走査線は出ない」と考えた例）、情報を伝えるという本来の役目を邪魔しないこと、がよく挙げられる。

### 6.2 見つけて直した所
| 見つけたAIっぽさ | 直し方（店の物） |
|---|---|
| 灰色のスクロールバー、灰色の四角のチェックボックス、黒い選択肢の一覧（Godot の既定のまま） | 起動時に既定のテーマを書き換える（`UI.install_theme()`）。スクロールバーは紙の罫線と鉛筆の細いつまみ、チェックボックスは印刷した四角に朱色のペンのレ点、選択肢の一覧は紙の一覧表で選んでいる行は蛍光ペン |
| 分類の切り替えが、角丸の枠のボタンを並べただけ（称号・記録） | 書類の**インデックスの耳**（`UI.index_tabs`）。選んでいる耳は紙と同じ色で下の線とつながる。左右の角の丸みを変えて、型抜きの手で切った感じに |
| 称号が「同じ大きさのカード × 2列」と、どのカードにも同じ枠の「つける」ボタン | **表彰の台帳**: カードをやめて罫線で区切った行。★は5つの欄（★☆☆☆☆）で、手に入れていないものは薄い。「つける →」は文字だけ、つけている行は蛍光ペン |
| ショップの「〇〇 HP で買う」が角丸の朱色の枠のボタン | **値札**（`Paper.PriceTag`）: 左がとがって、ひもを通す穴のある紙の値札 |
| ガチャの画面に主役（べた塗り）のボタンが2つ | 主役は「KAS の10連」だけ。ほかは値札 |
| 統計が「名前と数」の2列の表 | **業務日報**: 見出しで分け（シフト・お客さん・事件・対戦とショップ）、名前と数を点線のリーダーでつなぐ。0 の行は薄く、数のある行を濃く大きく |
| 対戦の掲示板が「同じ大きさの3枚」を横に並べた構成 | **コルクボード**（`Paper.Cork`）に**押しピンで留めた紙**（`Paper.PinnedNote`）。紙ごとに大きさ・高さ・傾き（-1.2〜1.6度）・ピンの色を変える |
| 開くシートがどれも同じ紙の箱 | 上の辺に**マスキングテープ**（`Paper.Tape`）。位置と傾きはシートの幅から決めるので、シートごとに少しずつ違う |
| 統計の見出しに古い名前（ハードコア） | 社員モードに直した |

### 6.3 追加の決まり
- **Godot の既定の部品をそのまま見せない。** 新しい種類の部品を使ったら、`UI.install_theme()` か `ui_kit.gd` で店の見た目にする。
- **同じ形のボタンを画面の中で別の役目に使わない。** 行動＝ハンコ（`UI.stamp`）、定型文＝紙のタグ（`UI.tag`）、買う＝値札、切り替え＝インデックスの耳、選ぶ・使う・閉じる＝文字だけ（`UI.link`）、主役＝べた塗り（`UI.primary`、1画面に1つ）。
- **一覧はカードの格子にしない。** 帳簿・台帳・日報のように、罫線で区切った行にする。カードにするのは、見本（名札・色）を見せる必要がある物だけ。
- **同じ大きさの物を等間隔に並べない。** 大事な物を大きく、ほかは小さく・ずらす（掲示板の紙）。
- **傾き・ずれは小さく（2度まで）、意味のある所だけ。** 掲示板・付箋・テープなど「人が手で貼った物」に限る。読ませる表（統計・設定）は傾けない。

6. 同じ形のボタンが、別の役目で並んでいないか。
7. 同じ大きさのカードを格子・横3つに並べていないか。
